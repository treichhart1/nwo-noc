# SMS security, operation and recovery

## Defaults and deployment boundary

`SMS_NATIVE_TRANSPORT_ENABLED=false`, `SMS_NATIVE_WORKER_ENABLED=false`, `SMS_CALLBACK_GATEWAY_ENABLED=false`, `SMS_EGRESS_APPROVED=false`. `SMS_WORKER_INTERVAL_SECONDS=5` is bounded5–300. Native transport requires explicit online mode and approved egress; legacy `NOTIFICATIONS_LIVE_DELIVERY_ENABLED` remains forbidden. The installer forces all new integration flags off and generates a private fifth `sms-callback` Fernet key. Existing encrypted backup/recovery includes all configuration keys. No source editing, production credentials or live provider activation is required for installation.

The optional deployment files are **operator-reviewed templates**, not automatically exposed services:

- `deploy/sms-callback-gateway.compose.yml`: standalone callback-only ASGI app, explicit optional profile, immutable image repository+SHA256, UID10001, read-only root, no capabilities, no-new-privileges, CPU/memory/PID limits, loopback18191. Health is process liveness only, not verified provider/DB health.
- `deploy/sms-callback-nginx.conf.example`: exact two POST routes, bounded requests, no private API proxy/access logs, default404. Add the documented http-level rate zone before use. Real DNS, trusted TLS, egress, firewall and separation require separate operator authorization. Do not append these routes to an unrestricted private-NOC catch-all.
- `deploy/sms-gateway-role.sql`: approved DBA applies after migration0029. It creates a NOLOGIN privilege group only. Provision a separate least-privilege login through the approved secret mechanism, grant that group, restrict pg_hba and private DB transport. It cannot read users/customers/API credential vault, clear consent, alter acceptance proof, enqueue sends or delete replay evidence. The SECURITY DEFINER function only adds opt-outs and returns no customer count.

The gateway environment needs its restricted DATABASE_URL, APP_ENV, independent random SECRET_KEY (not the private JWT signing secret), `SMS_CALLBACK_KEY_FILE=/run/secrets/sms-callback.key`, `SMS_CALLBACK_GATEWAY_ENABLED=true`; keep transport/worker/egress false. Do not mount the notification API-vault key. Mount only `/etc/nwo-noc/keys/sms-callback` read-only at the template target; file is private UID10001-readable. Backend/worker use the same callback key at their private keys path for contact fingerprints. A separate Docker private DB network and approved published immutable image identity are operator inputs. No callback endpoint creates/uses private NOC admin credentials.

## Consent, authentication and privacy

The private admin router is `/api/notifications/sms`, existing administrator JWT/RBAC only. API credentials are write-only encrypted using existing notification vault. Webhook verifier material and inbound body are encrypted with the separate callback key. Contact identities are HKDF-derived HMACs; generic logs/audits never include raw full numbers, credentials or bodies. Inbound plaintext requires explicit administrator review, with audit. Expired inbound ciphertext can be redacted through the admin endpoint; retain negative-consent/replay tombstones. Back up the callback key: losing it loses matching/decryption and requires controlled recovery, never a fresh key plus silent opt-out reset.

Callback authentication precedes quota. Invalid requests and identical replays cannot exhaust verified STOP's separate budget. Limits:16KiB request/3-second body read, bounded authenticated counters,5-second outbound HTTP/3-second connect,32KiB provider response, TLS validation, fixed API origins, no redirects/proxy environment. Native Twilio freshness limitation is documented separately. Callback identifiers/account/profile/owned sender/recipient must match; orphan verified status events are retained until exact receipt binding, never guessed onto unrelated customers.

STOP and21610/40300 enforce existing customer opt-out/suppression and immutable contact-negative evidence across providers. Unknown senders are not assigned invented accounts. START does **not** establish sufficient consent: review and a separately approved consent recovery process are needed; this release supplies no automatic reset endpoint. No HELP/customer reply autoresponder or promotional messaging. Provider-side automatic keyword replies/fees are outside NOC submission counters and require separate provider configuration/compliance review.

## Delivery and finance

Normalized delivery states include queued, submitted, accepted, sent, delivered, undelivered, failed, suppressed, reconciliation_required. Preserve raw status and error; terminal outcomes cannot regress to resendable. Database receipts/provider IDs are unique. Claims, leases and budget reservations commit **before** network I/O. A crashed/expired claimant becomes reconciliation_required, not retry. Independent-connection regression tests assert this ordering. Approved message fingerprints/config revisions bind release. Legacy simulation attempts cannot be repurposed as live release.

Failover defaults false. Only proven nonacceptance can retry/failover, with all current policy/consent/spend/content/registration/allowlist checks again. Secondary must be separately authorized. No timeout,5xx, accepted/queued receipt, delivery failure after acceptance or missing callback can trigger failover. GET404 is not rejection proof. Failed/retry rows and unresolved rows are retained as dead-letter/reconciliation evidence, with bounded attempts and manual cancellation via existing controls.

GSM7 extended characters and UTF16 segments are estimated; carrier segmentation may differ. Price per segment is configured in integer USD microunits (1USD=1000000); no hardcoded current prices. Null price/zero caps blocks live activation. Daily/monthly UTC reservations include unresolved/pending attempts; proven nonacceptance frees reservation. Reserve conservatively using the greater of configured estimate and provider-reported cost. Reports separate projected estimates, reserved/incurred amounts and provider-reported amounts. None is verified billed/collected cash. Usage is submission-time cohorts; delivery success uses known terminal outcomes, failure rate uses (rejected+failed)/all attempts, unresolved separately. Provider fees, inbound/automatic replies, taxes and delayed prices are not guaranteed bill caps: maintain provider-side limits too.

## Acceptance, troubleshooting and rollback

Before separately approved tests, verify sender registration/ownership, current terms/quiet hours/consent, callback signatures with vendor test evidence, NTP, isolated DB privileges, independent keys, private admin VPN/MFA, exact TLS URLs and current prices/caps. Use approved synthetic recipients; this assignment does not authorize real transmission. Health timestamps mean last observed submission/callback, not carrier availability or account funds. No callback means unavailable, not healthy.

Authentication errors: check correct API vs callback credential type without printing values. Signature failure: exactURL/headers/rawbody/clock/account; never disable verification. Rate rejection: honor bounded Retry-After, do not rotate providers around account policy. Ambiguous attempt: preserve evidence, stop secondary submission, reconcile exact receipt with provider records. Early callbacks stay orphaned until matching receipt; unknown callbacks never authorize resend. Reconciliation requires separate host egress authorization.

Emergency stop: existing notification emergency-disable plus provider disable, then worker host flag false. Keep callback verification available for pending receipts and STOP. Do not delete volumes, histories or tombstones. Restore matching database/config/documents/**all keys** from verified encrypted backup into isolated infrastructure before rollback; migration0029 downgrade refuses destructive consent/history loss. Re-enable nothing automatically after recovery. Existing signature/artifact/backup/upgrade gates remain mandatory; no production signing keys are created here.
