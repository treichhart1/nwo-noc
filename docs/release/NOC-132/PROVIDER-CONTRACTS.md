# Verified contracts and limitations

Reviewed official documentation 2026-11-28:

- [SendGrid Mail Send](https://www.twilio.com/docs/sendgrid/api-reference/mail-send/mail-send): v3 JSON, bearer API key,202 acceptance; custom arguments correlate a random committed attempt capability without customer IDs, PII or quote tokens. Store X-Message-Id when returned; its absence does not imply nonacceptance. Sender/from/reply-to constrained to approved domains.
- [Signed Event Webhook](https://www.twilio.com/docs/sendgrid/for-developers/tracking-events/getting-started-event-webhook-security-features): base64 DER P-256 ECDSA/SHA256 signature over exact timestamp header bytes plus raw request body. Independent public key from actual account; timestamp five-minute bound; persist authenticated event ID/body hash. This is not Twilio SMS request signing or Telnyx Ed25519.
- [Event reference](https://www.twilio.com/docs/sendgrid/for-developers/tracking-events/event): preserve provider events/message identity, normalize terminal evidence without claiming all provider queues or receipts identical. Bounce, complaint and unsubscribe immediately suppress the address across providers. Group unsubscribe conservatively suppresses all email; no marketing categories implemented.
- [Python smtplib](https://docs.python.org/3/library/smtplib.html): authenticated STARTTLS or SMTP_SSL using default trust/hostname verification. Stable Message-ID is a correlation aid, not an idempotency guarantee. An uncertain DATA response never permits automatic resend. No native inbound DSN or authenticated SMTP complaint contract was invented.

No provider-specific price, actual billing, domain verification, deliverability or live recipient acceptance was established. Open/click tracking is disabled. SendGrid Email Activity lookup depends on actual plan/permissions and is not fabricated here; manual evidence does not become a verified provider lookup. SMTP has no invented callback receiver. Signing-key rotation after accepted historical sends needs a reviewed retention/rotation plan. Quote token URLs remain forbidden by the existing contract; separately prepared canonical tokens may be included only in approved encrypted quote bodies. Existing APIs for quotes, policy acceptance, service status, Powercode, public publication and provider-independent incident ownership remain authoritative.

The email receiver uses a dedicated persistent EMAIL_CALLBACK_KEY_FILE for HKDF/HMAC identity matching. It must not receive the private NOC JWT signer or outbound provider-vault key; use independent unused settings-schema secrets and a restricted DB role. JWT rotation does not change suppression identities. Native identity-key replacement requires a separately reviewed suppression/evidence migration; never silently regenerate it.
