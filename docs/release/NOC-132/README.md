## Architecture and implementation

The canonical NOC-96 `notification_plans`, `notification_deliveries`, `notification_attempts` and encrypted `notification_credentials` remain authoritative. There is no second delivery queue, customer registry or incident system. Additive migration **0035_unified_communications** follows 0034 and introduces email configuration, immutable template revisions, purpose/identity evidence, shared email suppression, encrypted per-delivery envelopes and signed event records. Existing customer/applicant/cancellation/incident IDs are reused. The two existing provider-receipt columns are compatibly widened from100 to360 characters because a valid SMTP sender domain produced a123-character Message-ID in reproduction. Downgrade refuses to truncate any longer evidence; existing SMS input validation remains unchanged.

Native SendGrid v3 and authenticated STARTTLS/implicit TLS SMTP adapters have bounded timeouts and sanitized outcomes. Mock mode is explicitly offline staging. Provider acceptance, manual acceptance attestation, signed delivery events and simulated delivery are distinct. SMTP cannot establish final delivery. No open/click surveillance. HTML is generated from escaped plain text; arbitrary HTML, links, scripts, images/tracking pixels and template expressions are rejected. Branding supports text/support information and small validated inline PNG logos, without remote resources. Optional approved quote body tokens reuse the existing separately prepared canonical secure access; never URLs, subjects, generic logs, Slack or public plan metadata. Private email bodies/previews remain encrypted/no-store; token rotation or expiry invalidates approval.

Terminal email body cleanup honors canonical application/cancellation legal holds and never deletes receipts, suppression or uncertain claims. Email preferences are purpose-specific extensions of canonical subject records, not inferred from SMS or Powercode imports. Address verification requires an administrator's evidence reference. A dedicated persistent email-callback identity key is separated from private JWT and outbound credential-vault keys. The isolated public receiver must use an independent non-NOC JWT placeholder configuration; private JWT rotation cannot erase email suppression. Fresh installer provisioning, old-core disabled-by-default upgrade compatibility and restored-key identity checks are covered. Case-folded address suppression is deliberately conservative across SendGrid/SMTP, and cannot be cleared by provider or preference changes. Signup's explicit consent and withdrawal are rechecked. The verified email category is operational, maintenance, signup, installation, cancellation or retention; promotions are unsupported. SMS STOP never grants email permission; email suppression never modifies SMS consent. Cancellation processing remains independent of communications.

The central private notification screen displays all canonical queue channels, independent approvals, provider evidence and attempt history, including immutable verified event evidence. Private analytics separate resolved-attempt success rates (unknown/pending excluded and reported separately), confirmed SendGrid delivery fractions of unique accepted messages, non-additive bounce/complaint events, UTC day/month usage and currency-specific estimated/reported cost. SMTP/mock final delivery and unverified costs remain unavailable. Public WordPress publication references are read from the existing canonical publication model, never treated as customer delivery. Existing SMS, Slack, public status, signup and cancellation workflows retain their independent approvals. Email uses the same source IDs and requires its own exact-message approval; adding it does not approve another channel.

A worker commits its exclusive durable intent before I/O, releases global DB locks during transport, rechecks eligibility immediately before submission, and quarantines expired/ambiguous intents. No automatic failover. A proven rejection may be independently approved for a different independently authorized provider; accepted or uncertain attempts cannot. Only explicit rate-limit nonacceptance gets bounded automatic retries. Count/cost/rate/contact-cooldown controls reserve in-flight submissions conservatively. No exactly-once claim.
