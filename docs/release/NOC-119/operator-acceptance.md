# Operator acceptance — no live test is authorized by this milestone

## Trusted production publication

1. Resolve/review every open security and performance blocker with evidence. Do
   not change open_blockers to empty merely to satisfy the verifier.
2. Approve exact source SHA/tree and complete migration chain. Build on a reviewed
   isolated builder. Preserve all dependency/native reports and SPDX inventories.
3. Publish reviewed images only through the separately approved release process;
   pull by immutable registry RepoDigest and rescan those exact bytes. CI local
   config IDs are insufficient production registry evidence.
4. Bind backend/frontend/PostgreSQL/Redis, complete SBOM/dependencies/container
   reports and provenance to the same source/tree/registry digests. Independently
   review licenses, including Redis7.4.12, and any native scanner coverage gaps.
5. Use independently controlled production Ed25519 signing custody, never a private
   key on the NOC server. No production key is generated by NOC119. Sign exact
   approval bytes after evidence hashes and independent risk review are final.
6. Provision the trusted public key separately, record its SPKI SHA256 fingerprint
   through a separate authenticated channel, and protect approval/key/evidence
   files. Verify invalid signatures, changed manifests, wrong/missing artifacts,
   wrong image digests/source and unresolved risk rejection using disposable keys.
7. Production stage now saves release-trust/. Back it up encrypted with original
   signed files. Never trust a recovered public key solely because it is inside
   the same backup. Verify against the separately retained fingerprint and repeat
   evidence verification. Plan key rotation before replacing the trusted key.
   Legacy releases without a verified trust capsule require operator remediation;
   do not fabricate a signature, rewrite old backups or bypass preflight.

## Host and disaster recovery acceptance

- Verify an approved clean Ubuntu24.04 image, boot/kernel/architecture, resources,
  system updates, UTC synchronization, key-only SSH, administrator MFA and VPN
  identity enforcement. Guest SSH tunnel tests do not certify actual VPN/MFA.
- Default-deny inbound/outbound policy must separately cover host OUTPUT and
  Docker forwarding (including DOCKER-USER/nftables); verify from an independent
  unapproved source, includingIPv6. Keep dashboard loopback/private TLS, DB/Redis
  unpublished and application network internal. Do not open public ports by default.
- Permit only approved device endpoints/protocols, registry/update bootstrap,
  required DNS/NTP/CA and backup destinations. Use narrow windows for updates;
  capture firewall/egress evidence. Do not scan networks or enable integrations.
- Verify file owners/modes, dedicated service account, capability-free/read-only
  application containers, credential broker, log rotation/journald, audit retention,
  systemd dependencies/resource limits and startup after an actual kernel reboot.
- Deploy an approved malware scanner, secure socket permissions, current trusted
  definitions and bounded updates. Repeat safe EICAR, unavailable/timeout/restart,
  quarantine, approval and protected retrieval tests. NOC119's custom test signature
  database does not establish production signature currency.
- Configure encrypted off-host backups with independent custody of recovery keys,
  signed manifests, public fingerprints and registry access. Restore to a second
  independent failure domain. NOC119's two guests share a hypervisor; retain the
  site-disaster/physical failure-domain blocker until independently exercised.
- Restore PostgreSQL/configuration/document/encryption/Redis state into an empty
  host only; verify schema, constraints, user authentication, telemetry/history,
  documents, queue integrity, services, reboot and private bindings. Never silently
  restore over newer data. Retain failed backups and source records for review.
- Confirm a failed post-migration upgrade stops safely. Do not promise automatic
  database downgrade. Use the documented matching-release/database restore plan
  only after explicit operator approval and preservation of newer records.
