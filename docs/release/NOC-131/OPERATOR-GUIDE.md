# Operator guide

## Isolated installation and plugin

Use the reviewed NOC124/NOC123 installer, trust verification, NOC122 preflight and later handoff procedures. Existing installations use guarded `upgrade.sh` with verified encrypted backups and the complete migration chain; do not rerun fresh installation over an existing system or delete migration history. This milestone does not authorize a server or website deployment.

Build the deterministic plugin from the reviewed source:

```sh
python3 scripts/cancellation/build.py --output /tmp/noc131-plugin
(cd /tmp/noc131-plugin && sha256sum -c nwo-customer-cancellation.zip.sha256)
```

Inspect `plugin-manifest.json`. The CI cancellation artifact contains the same ZIP, checksum and member manifest. Do not upload secrets or application code as a plugin. In a separately authorized disposable WordPress, upload `nwo-customer-cancellation.zip` through Plugins → Add Plugin → Upload, activate per site, open Settings → NWO customer cancellation. Keep disabled until the gateway and policy are accepted. Approve the exact public HTTPS443 signup origin and DNS addresses, branding and height, save and run connection diagnostics. Add shortcode `[nwo_customer_cancellation]` or the NWO Customer Cancellation Gutenberg block. Default and classic themes and390px viewport have dedicated automated coverage; final job evidence determines actual passing versions. Deactivation preserves settings; uninstall removes only this plugin's settings/diagnostics and files, preserving pages and NOC history.

Reuse `examples/signup/compose.yml`, `signup.env.example`, `public-role.sql` and `nginx.conf`. Build `npm ci` and `npm run build:signup` with supported Node22; its output includes both signup and cancellation pages. The public gateway must use its restricted database identity, separate gateway secret, read-only signup encryption key mount and explicit Turnstile-only egress. The same encrypted record key must be available to the private application and recovery, under existing secure permissions. Configure an approved dedicated origin such as `https://signup.nwohiobb.com`, with public HTTPS terminated on a separately approved gateway; never route the private dashboard through it. Configure Cloudflare Turnstile hostname and existing `service_signup` action used by both forms. Keep fixture/test mode disabled outside isolated synthetic acceptance. Configure the public proxy's `frame-ancestors` to the exact approved WordPress origins. Do not enable broad CORS or wildcard private API proxying.

First log in privately as administrator and create an operator-reviewed policy version in Customer Impact → Customer cancellation and retention. Policy text may state that cancellation after monthly billing can leave the full month payable, but must not represent acknowledgement as enforceable debt or reject requests over balances. Configure reasons, competitor metadata and retention thresholds as required. After separate authorization, set `RETENTION_PUBLIC_ENABLED=true` in the gateway environment, preserving the enabled signup boundary and all existing checks. No private API accepts unauthenticated cancellations. Run `/public/cancellation/health` and plugin diagnostics. Until enabled, the form reports unavailable, never operational success.

## Review and retention

1. Review protected submission, immutable acknowledged policy and receipt. Public response is identical for known and unknown accounts.
2. Independently verify identity and address through approved company procedures. Never use receipt possession alone as identity proof. Search existing canonical customer records privately; verify the specific customer and comma-separated service IDs. A second service on an account is not implicitly selected or cancelled.
3. Record evidence reference and encrypted operator notes. Verification snapshots package, contracted/estimated recurring amount, currency, site and sector. Preserve reported reason; select a separate operator classification. Associate a known competitor or leave unknown. A customer-reported replacement offer does not prove coverage or independent pricing.
4. Record review/contact/technical investigation. Draft explicit eligible offers with expiration and estimated incremental costs. Independently approve exact fingerprint; record actual acceptance/decline evidence. Source service/package/pricing changes invalidate the offer. Mark retained only after customer acceptance and source-observed active selected services. Offers never apply discounts, equipment changes or billing commands.
5. Confirm cancellation, then await disconnection. The NOC does not perform disconnection. Record disconnected only after canonical source history has a verified transition and current service status is disconnected. Initial disconnected imports are not disconnection-date evidence. Close after review. Record equipment-return requirement, due date and observed return per selected service through the private equipment endpoint. Billing disposition records review only; Powercode controls actual charges/refunds/balances.
6. Use legal hold where required. Redaction requires closed/withdrawn request, configured retention expiration and no hold; it destroys the wrapped PII key and retains historical references. Restrict old backups according to company retention policy, since earlier recoverable backups may contain keys.

## Competitors, imports and reports

Initial configurable examples seed names only, with unknown technology and no prices/coverage. Add independently sourced observations with date, currency, standard/promotional price/duration, charges and contract conditions. Customer reports remain unverified; do not check verification merely because the customer supplied a price. Correct an observation by appending evidence, not rewriting history.

Historical CSV: select explicit supported column mapping, preview all rows, review unmatched customers/services and normalized reasons/competitors, apply the exact returned digest. Maximum1000 rows/500KB. Required stable import ID prevents duplicate or conflicting reimports. Dates must be chronological, nonfuture and ISO8601. Monetary fields require finite nonnegative two-decimal values and explicit currency. Invalid rows cause atomic rejection. Unmatched reports remain encrypted without fake associations or customer policy acknowledgement. Independently verify associations later. Retain the original source and audit reference securely.

For churn rates, import/attest complete month-opening and following-month-opening cohorts including every service for every account. Optional historical price/start-date/town/county evidence uses the documented cohort API. A current price or first import date is not historical evidence. Incomplete membership yields unavailable rates, not zero. Reports separate observed disconnect events from cohort attrition and recurring snapshots from billed/collected cash. Tower finance requires the matching canonical tower scope and reporting period. Review unknown pricing/reasons and mapping freshness before business decisions.

## Communications and recovery

Prepare cancellation SMS drafts only for verified canonical customers with current account consent **and request-specific permission for the confirmed canonical contact**. An unchecked public SMS box grants no permission for this request. In the private review screen, record actual affirmative purpose-specific permission and the independently verified canonical phone with its evidence reference, or record a withdrawal. This does not restore global/provider opt-outs or authorize delivery. Verified affirmative public submissions must match the canonical phone exactly. Approve through existing notification screens; explicitly authorize `customer_cancellation` for each independently approved Twilio/Telnyx sender/category, with pricing/budgets/quiet hours. Old authorizations do not gain this category. Existing shared STOP/opt-out/holds and ambiguous-acceptance quarantine apply across both providers. Cancellation processing remains available without SMS. Prepare Slack separately in the existing notification dashboard using source kind `cancellation`, identifier=request ID; approve exact safe source fingerprint/channel with existing controls. Never add customer names, phone, address, notes or financial text. Do not send messages during development.

Back up PostgreSQL, all configuration, uploaded documents and the existing signup master encryption key with the reviewed encrypted backup scheduler and independent destination. Restore in an empty disposable environment and verify a decrypted request/offer and immutable history before accepting recovery. Independent VM/second-host CI includes a synthetic encrypted request/key probe; this is not proof of physical off-site recovery on operator hardware.

On trouble, disable public intake and plugin integration without deleting requests; revoke pending notification approvals using existing controls. Inspect private system health and audit evidence, not customer data in generic logs. Gateway503: verify reviewed policy, restricted function grants, key permissions, database and enabled flags.409: refresh current policy/revision and retry exact reviewed submission, not a second account lookup.403: exact origin/CSRF/Turnstile/role/consent checks must be satisfied. Unknown churn: provide complete historical cohorts. Roll back only with matching reviewed release/database backup through existing recovery procedures; migration0034 refuses destructive downgrade.
