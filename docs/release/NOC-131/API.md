# API and deployment contract

All private endpoints below require an authenticated active administrator and financial access; no public route includes them. Responses are `no-store`. Writes have a1MiB stream bound, PostgreSQL transaction, bounded statement/lock timeout, advisory lock and optimistic `expected_revision`. Every mutating request includes encrypted operator `notes` (3–2000 characters). Private evidence reads are audited. Failed mutations roll back atomically.

- `GET /api/retention`: paginated50 rows, offset≤100000, exact status/reason/customer/service filters and reference search. No expensive unbounded PII text search.
- `GET /api/retention/cases/{id}`: decrypted protected submission, original policy/version/time, selected-service snapshots, last100 immutable events/offers and advisory evidence.
- `POST /policies`: `text`, optional retention_days(30–3650), unresolved_days(1–90), tower_churn_threshold; creates new immutable version and deactivates previous public policy. No acknowledgement debt or fee generation.
- `POST /reasons`: code,label,voluntary(`voluntary|involuntary|unknown`),active.
- `POST /competitors`: name,technology,service_areas,active. Names seed as configurable examples only.
- `GET/POST /observations`: competitor_id, `offer` with provider/technology/package/download_mbps/upload_mbps/currency/monthly/promotional/promo_months/promo_expires/installation/equipment/contract, source_kind/reference,date,verified. Customer-reported offers cannot be independently verified by that same source. Append corrected evidence; no historical overwrite.
- `POST /cases/{id}/verify`: expected_revision,notes,customer_id,distinctservice_ids,identity_verified,address_verified,evidence_reference. No implicit all-service selection.
- `POST /cases/{id}/review`: revision,notes,competitor_id(nullable),legal_hold.
- `POST /cases/{id}/status`: revision,notes,status,operator_reason(nullable),billing_disposition (`unreviewed|refer_powercode|reviewed_no_change|refund_review|charge_review`). State graph: pending_verification→verified/withdrawn; verified→retention_review/cancellation_confirmed/withdrawn; retention_review→cancellation_confirmed/withdrawn; cancellation_confirmed→awaiting_disconnection/withdrawn; awaiting_disconnection→disconnected/withdrawn; disconnected/withdrawn→closed. Source evidence is required for disconnected. No external writes.
- `POST /cases/{id}/retention`: revision,notes,state,evidence_reference. Explicit offer decision endpoint handles accepted/declined; retained additionally requires observed active selected services.
- `POST /cases/{id}/equipment`: revision,notes,service_id,required,due,returned.
- `POST /cases/{id}/offers`: revision,notes,kind,terms,aware expires_at,eligible,evidence_reference,estimated monthly_cost/one_time_cost,currency. `POST /offers/{offer_id}/decision` relative to case: revision,notes,fingerprint,action(`approve|accepted|declined`),evidence_reference. Expiry and current source context are rechecked. Actual acceptance evidence is immutable.
- `POST /cases/{id}/redact`: revision,notes; configured expiry/closed/no-hold checks required.
- `POST /cases/{id}/sms-draft`: revision,notes,template(`request_confirmation|retention_contact|equipment_return|processing_update|completion`). Returns existing notification plan ID/fingerprint only; no delivery authorization. Any later case change invalidates older drafts.
- `POST /cohorts`: first-of-month `as_of`, complete,distinctservice_ids,evidence_reference; optional `evidence` mapping canonical service ID→{monthly,currency,basis(contracted/estimated),started_on,town,county}. Complete historical membership is an explicit operator attestation, never inferred from current active status. Snapshots are immutable.
- `POST /historical-import`: csv_text,columns mapping,dry_run(defaulttrue),expected_digest for apply. Supported fields: external_id,customer_external_id,service_external_id,requested_date,disconnected_date,reason,competitor,town,county,comments,monthly,currency. No Powercode changes; unmatched retained for review.
- `GET /analytics?month=YYYY-MM&site_id=…`: monthly calculations and unknown-data counts; `/trends?start=YYYY-MM&months=1..12` repeats bounded monthly periods. `/towers/{id}` accepts optional matching finance_period_id/finance_scope_id for the canonical profitability result. `/geography?month=…` returns private existing site coordinates and observed cancellations only.

Dedicated public signup ASGI application adds only `GET /public/cancellation/config`, `POST /public/cancellation/requests` and `GET /public/cancellation/health`. Config returns current policy/reasons/CSRF/Turnstile public site key. POST requires a UUID submission_key, name,email,E164phone,address,requested date,reason,policy_id,explicit equipment/policy/privacy acknowledgements,optional SMS consent,Turnstile and optional replacement offer/comments/town/county/account reference. No account ID lookup exists. Exact idempotent retry returns the same generic reference/secret receipt; changed payload conflicts. Secret receipt is not account authentication and reveals no account existence or current status.

The public PostgreSQL role receives only execute rights for `noc_cancel_config`, `noc_cancel_replay` and `noc_cancel_submit`, alongside existing signup rate/CAPTCHA infrastructure. SECURITY DEFINER functions use a fixed `pg_catalog` search path and fully qualified application tables, atomic per-key locks, fixed insert columns and input checks. No private customer/case/offer/finance SELECT is granted. The public reverse proxy only forwards `/public/signup/*` and `/public/cancellation/*` and serves reviewed assets; all `/api/*` routes remain404. Separate production TLS/egress/WordPress authorization is mandatory.
