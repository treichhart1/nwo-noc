## Architecture and implemented boundaries

The existing Powercode customer/service records remain authoritative. Append-only NOC130 source-status history supplies observed disconnection evidence. A cancellation request references an independently verified account and an explicit subset of its services; it never alters those services, billing, packages, payments or network configuration. Unknown historical submissions remain encrypted and unmatched. Initial disconnected imports do not establish cancellation events or historical subscriber denominators.

Normalized cancellation requests, selected-service snapshots, immutable events, reason configuration, immutable policy versions, competitor observations, retention offers, historical subscriber cohorts and import runs share existing user/customer/site/sector references. A per-request wrapped encryption key protects submission data, customer comments, operator notes, offer terms and customer decision evidence using the existing signup encryption facility. Closed expired records may be cryptographically redacted only without a legal hold; historical identifiers and aggregate financial snapshots remain preserved.

The existing Customer Impact screen has an administrator-only cancellation dashboard, request history, identity/service review, reason and competitor review, retention actions, independently approved offers/customer decisions, SMS drafts, monthly analytics, historical import preview and policy/cohort configuration. Private geographic views reuse existing canonical site coordinates; the public gateway never exposes them. Tower reports reuse the existing finance scope calculation rather than duplicating profitability or allocating costs a second time.

The standalone WordPress plugin embeds `/cancel.html` from the approved dedicated signup gateway. It stores only administrator configuration in WordPress, not cancellation submissions. It retains the reviewed plugin transport's HTTPS443-only origin validation, public-address allowlisting and pinning, verified TLS, disabled redirects, bounded response size/timeouts, administrator capabilities/nonces and escaped rendering. Public request endpoints have no account lookup, no account existence response and no private API routes. Restricted SQL functions can only return policy/reasons and insert encrypted requests/events; public roles receive no cancellation/customer/financial table grants.

Public intake remains disabled by default (`RETENTION_PUBLIC_ENABLED=false`), requires the existing enabled public signup boundary, exact-origin CSRF, Turnstile, bounded inputs, atomic rate budgets and idempotency. Optional submitted SMS consent is a report, not permission to overwrite canonical consent or restore an opt-out. Processing never depends on SMS consent.

Cancellation SMS drafts reuse canonical NotificationPlan/Recipient, approval fingerprints, outbox, native Twilio/Telnyx, shared opt-outs, quiet hours, provider authorization, budgets and reconciliation. `customer_cancellation` requires separate provider-category authorization and is excluded from new default category grants. No fake customer, prospect or incident is created. Slack uses a separate allowlisted cancellation source with safe IDs/state only and its own existing authorization/approval; it never copies comments, contact/address, offer text or finances. Actual overdue/unresolved/trend evidence drives those optional draft classifications. Neither channel is sent or enabled by this milestone. Native email is still unavailable; bounded NOC132 work must reuse the same approvals/outbox, define verified email/opt-out identity, provider-specific acceptance/reconciliation and secure callbacks, and add synthetic tests before any separately authorized delivery.
