Powercode remains authoritative for accounts, billing, payments, package assignment and activation. NOC95 already provides canonical customer/service synchronization, cursor continuity, failure health, source tombstones, network mapping, impact and local consent. NOC129 already provides encrypted applicants, reviewed quotes, installation work orders and documentation-only provisioning preparation. This milestone extends these models; it creates no duplicate customer database, billing engine, notification queue or incident.

## Implemented

- Existing synchronization accepts optional, bounded package observations and LTE/5G service types, recurring charges with explicit currency/contracted-or-estimated basis and package references. Incomplete snapshots still fail atomically; omissions are processed only under the existing complete/full contract. Consent/opt-outs and stable local/network identities remain canonical.
- Append-only service status history retains active/suspended/disconnected changes, including existing full-snapshot tombstones. No cancellation or external write is performed. This is the source foundation for future cancellation analysis, not an automated retention/cancellation engine.
- Administrator-reviewed package-to-signup-plan mappings bind current package content and plan revision. Changed packages/plans invalidate mappings. Import never publishes a plan or overwrites signup pricing. Unknown native recurring/billing fields remain unavailable.
- Private Powercode administration in the existing Customer Impact screen shows blocked connection state, synchronization counts/history, unmapped services, duplicate contact warnings, package mappings, provisioning states/identifiers and charge observations. Credentials use the existing encrypted vault and are never returned.
- Exact encrypted provisioning previews require documented identity/address/qualification/duplicate review, latest approved accepted quote (public append-only or legacy encrypted acceptance), completed canonical installation work and existing approved signup preparation. A unique application record and immutable preview fingerprint prevent duplicate preparations and stale approvals.
- Independent administrator approval and queueing are distinct. A synthetic-only, explicitly injected worker commits submission intent before mock transport; verified identifiers commit before later steps. Live leases are not reclaimed. Expired submitted intent or ambiguous response quarantines without automatic account retry. Partial failure preserves the created account identity. No compensating account deletion exists.
- Activation authorization is independently recorded, never executed; invoice/payment/cancellation/router operations do not exist. All native connectivity is disabled even if a future origin/credential has been prepared. Emergency disable also blocks synthetic worker execution. No production worker or scheduler registers this simulation.

Migration0033 follows0032. Adds integration control/package/mapping/history/provision/attempt/event tables and nullable canonical service financial fields. Foreign keys, unique application/operation keys, queue indexes, append-only evidence and immutable external IDs/preview triggers preserve history. Public integration roles receive no new table access. All historical migrations remain unchanged. Downgrade refuses destructive history removal; use matching reviewed backup recovery.
