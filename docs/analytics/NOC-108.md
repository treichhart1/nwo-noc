## Storage and architecture

Migration `0027_grafana_analytics` is additive, based on `0026_network_finance`.
Eight small tables hold revisioned configuration, bounded health checks,
provisioning receipts, immutable report snapshots, hourly aggregate bins,
coverage/invalidation markers, projection health and scrape budgets.
`noc_analytics` security-barrier views select approved scalar measurements from:

* Native telemetry: CPU/RAM, temperature, latency/loss and traffic.
* Existing MikroTik JSON: uptime, OSPF counts and up to16 interfaces per sample.
* NOC-89 normalized RF history: RSSI/SNR/noise/capacity/throughput/utilization,
  quality and modulation metrics where actually collected by vendor adapters.
* NOC-98 tower records: measured power, battery, UPS, temperature and sector data.
* Native monitor checks, incident lifetimes, equipment identifiers, service-record
  references, IPAM/topology counts and separate RF calibration comparisons.

There are no raw payloads, device names, IP addresses, interface names, customer
identifiers/contact details, secret values, financial amounts or incident notes
in the Grafana reader schema. Stable numeric NOC IDs provide tower/device filters.
Core/interface/monitor historical site attribution uses **current inventory**;
RF and tower records retain recorded site associations. Do not infer historical
ownership solely from current-inventory attribution.

Observed RF history and planning predictions remain distinct. Calibration values
are comparisons, not measured telemetry replacements. Missing or invalid values
remain null; they are never silently converted to zero or healthy.

## Configuration and authentication

All external connectivity/export/scheduling is disabled by default.
Configure the exact private HTTPS origin in `GRAFANA_ALLOWED_ORIGINS` (comma
separated; no paths). An administrator then saves the private HTTPS server URL
and closed dashboard UID allowlist in Network Analytics. Safe optional URL
subpaths are supported. Redirects and arbitrary dashboard IDs are rejected.
Use VPN-only DNS/routing, TLS certificate verification, and firewall restrictions.
No public DNS/service exposure is required or recommended.

Default navigation opens a separately authenticated Grafana session. NOC JWTs,
passwords and tokens are never appended to dashboard URLs or forwarded.
Disable anonymous access, sign-up and public dashboards in Grafana. Use Viewer
accounts and a Viewer service account for health reads. Editors/admins are trusted
infrastructure roles and must not be granted to ordinary operators.

`GRAFANA_LIVE_HEALTH_ENABLED=true` is a separate explicit opt-in; it performs only
GET health, datasource health and approved dashboard reads with 1s connect/2s read
and an overall15s budget. No redirects, proxy-environment inheritance or remote
administrative writes. Store its service-account token in an application-owned
0600 regular file (`GRAFANA_SERVICE_TOKEN_FILE`); symlinks are rejected.
A failed check returns fixed error classifications, never response bodies or secrets.
Synthetic health is available only in offline synthetic staging and is explicitly
marked mock; it never establishes real connectivity.

Embedding is disabled. It additionally requires `auth_proxy`,
`GRAFANA_EMBED_APPROVED=true`, and explicit administrator configuration. Before
using an iframe, validate trusted proxy identity headers, Grafana role mapping,
HTTPS cookie/SameSite behavior, CSP frame-ancestors and browser authorization.
This milestone provides safe links; it does not claim tested SSO/embedding.

## Provisioning and private deployment

The templates use Grafana's built-in PostgreSQL datasource and file provisioning;
no plugins or remote provisioning writes are required. JSON files containing
provisioning objects are valid YAML1.2 and use `.yaml` filenames.
Contract parsing accepts Grafana11–13 response shapes; mock fixtures use12.3.3.
Only the actual container acceptance evidence in the test report establishes a
specific tested version. Operator vulnerability review and a current patched,
reviewed image digest remain deployment prerequisites.

Generate files in an **empty owned absolute directory**, using the release backend:

```sh
cd backend
python -m app.analytics.provision --output /absolute/private/provisioning
```

Files are0600 and directories0700. Set appropriate ownership for the Grafana
runtime user472; do not make secret files world-readable. The private optional
Compose overlay `deploy/compose.grafana.yml` publishes no ports. A reviewed VPN
reverse proxy must explicitly join its internal network before access is possible.
Do not expose the default Grafana admin UI through a NOC route.

Generate a random hex reader password into a private file (48–128 hex characters),
then run using the privileged migration connection:

```sh
python -m app.analytics.reader_role --password-file /absolute/private/reader-password --approve-private-reader
```

This creates `noc_grafana`, a non-superuser, no-inheritance, no-bypass-RLS login
with SELECT on approved views only, connection limit4, default read-only transactions,
5s statement timeout,10s idle transaction timeout and no public-table grants.
Provisioning aborts if inherited PUBLIC grants or callable SECURITY DEFINER
functions would expose protected tables. Review existing privileges first.
These defaults are resource guardrails, **not a sandbox against arbitrary hostile
SQL**: trusted Grafana datasource users can submit SQL and may alter session
settings. Use a dedicated read replica/resource policy for less-trusted users.

Set `NOC_GRAFANA_PG_HOST`, `NOC_GRAFANA_PG_SSLMODE=verify-full` and the secret-file
paths from the overlay. Use a trusted CA for private PostgreSQL TLS. Never use
`disable` outside an explicitly isolated disposable test. The secret wrapper reads
the DB credential into the Grafana process environment; protect container inspection
and database datasource administration access accordingly.

## Metrics, limits and retention

Optional Prometheus: `/api/analytics-scrape/v1/metrics` accepts only a separate
Bearer secret from `ANALYTICS_METRICS_TOKEN_FILE`. Administrator configuration
must explicitly select ≤100 existing device IDs and ≤20 approved metrics.
No interface/customer names or arbitrary labels; per-interface identity is a hash.
At most5000 series and60 scrape requests/minute. Missing/stale values are omitted;
last-observed timestamps are metric values, not high-cardinality labels.
Authenticated admin/operator `/api/analytics/v1/metrics` applies the same scope.

Native query windows1h,24h,7d,30d,90d/custom are bounded to retention and240 requested
time buckets, ≤5000 returned rows,100000 native or250000 derived source rows.
Narrow a tower/device filter when a budget is exceeded. No hidden truncation.
Aggregates use sum/count, not mean-of-means. Averages are sample-weighted and do
not establish time-based availability SLAs. Interface counters are counters, not
inferred throughput or capacity. Utilization uses recorded adapter measurements;
configured interface speed is not available measured capacity.

Set `ANALYTICS_ROLLUP_ENABLED=true` only after reviewing load, then run
`python -m app.analytics.worker --once` periodically or its300s loop. It aggregates
the last two closed UTC hours using advisory locks and no device transports.
A private audited administrator can backfill ≤24 closed hours per request through
`POST /api/analytics/v1/rollups`. Backfill in bounded batches for90-day reports.
Late native INSERT/UPDATE invalidates the affected coverage marker transactionally;
rebuild those older hours explicitly. The worker's two-hour window cannot repair
arbitrarily old late data automatically. Native API long-range results use cached
hours only when **all** requested closed hours have complete coverage, plus native
partial edge hours. Otherwise they use bounded native data or refuse an oversized query.
Grafana ranges above24h use prepared hourly bins; consult the coverage panel for
missing/incomplete hours. Do not interpret absent cache rows as no outages.

Derived retention is configurable1–90 days. The administrator retention action
prunes ≤1000 old derived bins per call; native telemetry/incident pruning policies
remain unchanged. Existing defaults: RF raw30days with pruning disabled;
RF projection90days with pruning disabled. Rollups preserve retained evidence if
raw pruning reduces source counts. Do not expect an aggregate to reconstruct
pruned raw samples. Snapshot reports are immutable and require a separately
reviewed retention policy; this milestone does not silently erase audit evidence.

## Reports and operations

Open Network Analytics from the existing NOC navigation. Select period, metric
and native tower/device identifiers; load the recorded report. Tables and charts
show recorded measurements and gaps. CSV exports are audited, authenticated and
restricted to the same numeric/scalar results; use browser Print for printable
reports. Saved snapshots retain their inputs, evidence and SHA-256 digest.
Related records link the operator back to the NOC; no second inventory exists.

Incidents are authoritative: range-clipped durations and recorded customer-impact
estimates are reported without creating duplicate incidents. Recurrence is not
proof of physical root cause. RF/capacity/power summaries require repeated
consecutive recorded buckets and cite their time range and samples. They are
advisory, not forecasts, financial advice, configuration writes or dispatches.

Integration health distinguishes disabled, mock/unverified, stale and unavailable.
It shows native/RF freshness, worker heartbeat/backlog, last remote check and
projection state. Provisioning receipts mean **exported**, not installed remotely.

## Recovery, backup and rollback

Use existing release backup/restore procedures for PostgreSQL and configuration.
Also back up the private Grafana data volume, reviewed provisioning files and
credential files with encrypted restricted storage. Never place credentials in Git.
Restore into an isolated database, apply migrations, re-provision/check reader
grants and verify a mock report before allowing any private connection.
Worker crashes roll back uncommitted bins; retry replays closed hours idempotently.
No source telemetry or incidents are deleted by rollup recovery.

Emergency disable: set integration enabled=false; stop the optional Grafana and
rollup services; unset live health/export credentials; revoke reader login and
restrict network access. Native monitoring continues independently.
Before downgrading27→26, back up NOC108 configuration/snapshots/derived aggregates,
stop analytics processes and deploy the matching old code. Downgrade removes only
NOC108 tables/views/triggers; it cannot preserve NOC108 snapshots by itself. Existing
telemetry, incidents, customer records and upstream migrations are retained.
